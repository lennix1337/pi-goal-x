## Context baseline rationale

The previous baseline excluded active-tool filtering and SDK guidance and did not actually exercise several named states. Replacing it is a measurement correction plus an intentional interface update, not a claim against those earlier incomplete counts. CONTEXT-BEFORE.json and CONTEXT-AFTER.json use identical corrected capture code against original HEAD and the candidate. The committed main context baseline tracks final behavior; historical benchmark campaigns remain untouched.

### 2026-10-24 refresh (fork: conversational budgets and authorized resume)

Fork commits `c97e4a1` (conversational run/token limits, 30-run default stated when omitted) and `61e1f634` (resume only on an explicit user request) changed the model-facing surface; the fork's CI had never run, so the gate first reported the drift on 2026-10-24. A first-parent bisect from `a77891b` passes through `64c5ace` and fails first at `c97e4a1`. Semantic counts are unchanged in all 24 fixtures. Every size field grew: SDK guidance +211 to +558 characters (the drafting rule for explicit limits and the resume rule), tool schemas +226 to +316 (`update_goal` resume), goal-state messages +114 to +251 in 17 fixtures. Estimated tokens over the 24 fixtures went from 69,389 to 75,030 (+8.1%, +114 to +321 per request). The growth is intentional and user-requested; reducing it belongs to a later context campaign, not to this refresh.

### 2026-10-24 refresh (fork: agent-resumed goals)

Fork commit `5409275` (user request: a goal the agent paused, or one stopped by a provider or quota outage, resumes without a new user authorization; a user pause still needs the user) rewrote the `update_goal` resume rule and the paused/blocked goal-state text, and added the rule that the agent pauses only when every remaining path needs a user-only action. The gate failed on CI run 40142630049. The pause rule was then stated once in the `update_goal` guidelines instead of three times (it was repeated in the lifecycle line and the agent-paused state), which saved 74 tokens. Semantic counts are unchanged in all 24 fixtures; 19 fixtures grew: SDK guidance +298 characters, tool schemas +155, messages -39 to +450. Estimated tokens over the 24 fixtures went from 75,030 to 78,164 (+4.2%). The growth is intentional and user-requested.

### 2026-10-29 refresh (fork: the auditor ignores which model executed the goal)

The operator asked that a goal accept whichever model executes it: an audit had refused completion only because a quota failover moved the work from the executor named in the objective to another model. The auditor prompt now says the executing model, provider or account (failover included) is never a reason to disapprove. Only the auditor's child request grew: `audit-rejection-and-rework` and `completion-audit` +218 characters each; main-session tokens and semantic counts are unchanged in all 24 fixtures (78,801 estimated tokens before and after), child request characters 15,228 to 15,664.

### 2026-10-28 refresh (fork: blocked goals keep update_goal)

Fork commit `11f2076` finishes the agent-resumed-goal request above: a blocked goal kept no `update_goal`, so the agent could not resume it once the blocker cleared; it now keeps the tool, and `get_goal` names `/goal-clear`.
